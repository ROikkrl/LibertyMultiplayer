# LibertyMultiplayer — сервер для Ubuntu 22.04

Сервер на Rust поддерживает до четырёх игроков. Для 0.2.17-test используйте Windows-лаунчер 0.2.17-test. При несовпадении версий сервер сообщает свою версию и блокирует вход и успешный пинг.

## Запуск

Распакуйте архив на сервере и выполните из папки `server-rust`:

```bash
bash start-server.sh
```

В архив включён статический бинарник Linux x86‑64. Первый запуск создаёт случайный ключ в `session.key`. Сервер работает в текущем терминале. Для остановки нажмите Ctrl+C. Параметры можно переопределить переменными `LF_BIND`, `LF_PORT` и `LF_KEY_FILE`. Если запускать из исходников без готового бинарника, установите Cargo. Скрипт сам соберёт release-версию.

Потоки обработки UDP проверяют подписи пакетов параллельно. Пакеты одного клиента проходят через один поток, а действия над общим миром применяются последовательно. По умолчанию сервер использует до четырёх сетевых потоков по числу доступных логических процессоров. Чтобы указать число вручную, запустите `LF_WORKERS=4 bash start-server.sh`. Допустимы значения от 1 до 8.

## Подключение

Если UFW уже включён, разрешите входящий UDP:

```bash
sudo ufw allow 24840/udp
```

Если публичный IP у роутера, пробросьте UDP 24840 на локальный адрес Ubuntu. Проверьте, что сервер слушает порт, из второго терминала:

```bash
ss -lun | grep ':24840'
cat session.key
```

В лаунчере укажите публичный IPv4, порт 24840 и ключ из `session.key`. Из домашней сети можно указать локальный IPv4 Ubuntu. Передайте ключ другу приватно. Пакеты подписаны общим ключом HMAC-SHA256, координаты передаются без шифрования.

Кнопка «Проверить сервер» проверяет ответ с тем же ключом, не занимая место игрока. Полный журнал доступен по умолчанию в `server.log`. Путь можно изменить переменной `LF_LOG_FILE`.

В `server.log` записываются подключения и отключения с IP игрока, выбор хоста с индексом мощности и временем в игре, резервирование и смена владельца машины. При отключении через F9 сервер пишет `reason=client`. Если пакет отключения не дошёл, сервер удаляет игрока по тайм-ауту.

Интерактивный терминал обновляет экран раз в секунду. В таблице видны хосты, IP, время текущего подключения и приоритет. Над таблицей показаны суммарная загрузка CPU всех потоков сервера, память RSS, скорость UDP, число сетевых потоков и пакеты, отброшенные из-за заполнения очереди. При запуске в фоне или с `LF_SCREEN=0` данные доступны в `server-status.json` по пути `LF_STATUS_FILE`.

```bash
watch -n 1 cat server-status.json
```

## Синхронизация окружения

Клиенты отправляют снимки окружения примерно 10 раз в секунду. Клиент рядом с центром ячейки карты публикует новые машины для неё. Действующие машины остаются закреплены за симулятором, пока он рядом и присылает обновления. Для прохожих действует приоритет хоста. Он равен индексу мощности (0.01–0.99), умноженному на число полных секунд текущего подключения (до 3600). Новое подключение начинает отсчёт с нуля. Для разных эпизодов источники выбираются независимо. Снимок передаётся максимум в 12 страницах по пять записей. При подтверждении посадки сервер исключает исходную машину из трафика в том же обновлении, в котором принимает нового водителя.

Состояние машин хранится отдельно от снимков источника. Если источник уезжает или выходит, сервер может передать симуляцию машины другому клиенту рядом с ней, сохранив идентификатор. Клиент, которому передана машина, продолжает её симуляцию локально в GTA IV.

Устаревшие пакеты движения получают актуальный ответ и не меняют состояние игроков. При потере частей снимка сервер и клиент запрашивают только недостающие страницы с ограничением в одну попытку для каждого снимка. При обрыве связи слот игрока сохраняется до восьми секунд.
